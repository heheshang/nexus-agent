## Description

架构文档 §6.1 的 **P1 核心类型**第三部分：把 §2.6 的三层错误模型与 §2.6.4.1 的 42 个业务码搬进 `nexus-core`。

### 三层错误（§2.6.1）

| 层 | 类型 | 谁处理 |
|---|---|---|
| 领域错误 | 各领域的 enum（`thiserror`） | 领域内部 |
| 应用错误 | `AppError` | 用例层 → 协议层 |
| 传输错误 | `axum` 的 `IntoResponse` | 协议层（**P5，不在本任务**） |

### 失败分类是第一公民（§2.6.3）

```rust
pub enum RetryPolicy {
    Retryable,      // 明确失败，重试安全
    UnknownOutcome, // 结果未知，重试可能产生重复副作用
    Terminal,       // 明确失败，重试无意义
}
```

**`UnknownOutcome` 是本设计相对参考实现的关键改进**：参考实现的 `IsRetryable` 把 504（超时）与 502（明确不可用）一视同仁，但 504 意味着上游**可能已经执行了副作用** —— 支付类工具在 504 下重试会重复扣费。

### 内部原因绝不外泄（§2.6.5）

```rust
pub struct UserFacing {
    pub code: ErrorCode,
    pub message: Cow<'static, str>,
}

pub struct AppError {
    pub facing: UserFacing,
    pub cause: Option<Arc<dyn Error + Send + Sync>>,  // 只进日志，绝不序列化
}
```

`UserFacing` 在**类型上**就无法携带内部原因。

### §2.6.4.1 业务码表（定稿，42 个）

码段沿用参考实现：1=参数 2=认证 3=会话 4=限流 5=LLM 6=RAG 7=工具 8=协议 9=系统。

**两处「看着像笔误」的地方是参考实现的原样，必须原样保留**：
- 码段 6 从 `60002` 起（没有 `60001`）
- 码段 9 的 `90002` 在 `90003` 之前

改号会让已上线的前端分支逻辑失效。

**`ErrorCode` 必须手工实现 `Serialize`** —— derive 会输出变体名 `"ModelTimeout"` 而不是数字码 `50002`，那会破坏「前端按码段通用处理」的语义（附录 C.1 陷阱）。

### 依赖

需要 NEX-4 的 `ErrorCode` 引用 ID 类型吗？不需要 —— 但 `AppError` 的 `Error` 变体里若有 ID，需要。

## Acceptance Criteria

- [ ] #1 `nexus-core` 有 `error` 模块，含 `ErrorCode`（42 个变体）、`RetryPolicy`、`UserFacing`、`AppError`
- [ ] #2 `ErrorCode` 的**码值、HTTP 状态、失败分类**与 §2.6.4.1 表**逐条一致**，由契约测试固化（对照表断言变体名 + 码值 + HTTP 三元组）
- [ ] #3 `ErrorCode` **手工实现 `Serialize`**，输出数字码（`50002`），**不** derive
- [ ] #4 `ErrorCode::segment()` 返回码段（1–9），且与码值前两位一致
- [ ] #5 `AppError::retry_policy()` 的分类与 §2.6.4.1 表的「失败分类」列逐条一致 —— 尤其 6 个 `UnknownOutcome` 码（`ModelTimeout` / `ToolFailed` / `ToolTimeout` / `SandboxTimeout` / `McpToolFailed` / `A2ATaskFailed`）
- [ ] #6 `UserFacing` 只含 `code` 与 `message` 两个字段 —— **类型上**无法携带内部原因
- [ ] #7 内部原因**绝不出现在** `UserFacing` 的序列化结果里（有测试断言）
- [ ] #8 `AppError` 实现 `Display`（含 cause，供日志用）与 `std::error::Error`
- [ ] #9 领域错误是 **enum** 不是字符串（至少落地一个示例领域错误，如 `ModelError`，演示 `#[from]` 转换与穷尽匹配）
- [ ] #10 码值唯一性有测试（无重复码）
- [ ] #11 `cargo test --workspace --locked` 通过；`cargo clippy --workspace --all-targets --locked -- -D warnings` 零告警；`cargo fmt --all --check` 通过
- [ ] #12 CI 六道门禁全绿（含 `scripts/check-naming.sh`）

## 备注

- 「传输错误层（`axum` 的 `IntoResponse`）」属于 **P5 协议层**，不在本任务 —— `nexus-core` 不依赖 `axum`。
- 架构文档未明确 `AppError` 是否需要 `From<ModelError>` 这类具体领域错误转换。本任务只落地 `ModelError` 作为**示例**，具体领域的错误 enum 随各 crate 落地时再定 —— 但转换的**模式**（`#[from]` + 穷尽 `match`）必须由示例确立。
